# PARALLAX — Script Usage Guide

## Overview

PARALLAX is a course system where students write paper reviews, then compare them against
machine-generated "Gauntlet" reviews. The pipeline has three phases:

1. **Gauntlet** — Generate machine reviews for each paper (done externally, stored in `gauntlet-reviews/`)
2. **Consolidate** — Assemble the best parts of each Gauntlet review into a `CONSOLIDATED_REVIEW.md`
3. **Evaluate** — Blind LLM comparison of student review vs Gauntlet, or ablation studies vs each other

## Scripts

### 1. `scripts/consolidate.py`

Builds `CONSOLIDATED_REVIEW.md` from a student's `gauntlet_review_N/` directory by
extracting the best sections from `dr_microarch_reader_review.md`, `prof_workloads_reader_review.md`,
and `SYNTHESIS.md`.

**Section mapping:**
- Q1 ← `dr_microarch_reader_review.md` (full content, stops before Discussion Questions)
- Q2 ← `SYNTHESIS.md` section 3: The Magic Trick
- Q3 ← `prof_workloads_reader_review.md` sections 1–4 (stops before section 5)
- Q4 ← `SYNTHESIS.md` section 4: Skeleton in the Closet
- Q5 ← skipped

```bash
# Single student, paper 1
python scripts/consolidate.py ardubal --review 1

# All students, paper 2
python scripts/consolidate.py --all --review 2
```

---

### 2. `scripts/evaluate.py`

Blind Gemini evaluation comparing a **student's review** against the **Gauntlet CONSOLIDATED_REVIEW**.
Runs 3 rounds with randomized A/B assignment to reduce position bias.

Scoring rubric: 6 dimensions (Mechanistic Accuracy, Insight Depth, Critical Rigor,
Breadth of Perspective, Calibration, Usefulness), each 1–5. Summary table shows
Gauntlet vs Human averages with delta.

Output: `<student>/evaluation_paper<N>.md`

```bash
# Student's paper 1 review vs Gauntlet
python scripts/evaluate.py ardubal --review 1

# Paper 2
python scripts/evaluate.py ardubal --review 2
```

---

### 3. `scripts/ablation.py`

Runs a 3-study ablation on a paper PDF using Claude Opus 4.5. Studies compare
different prompting approaches:

- **Study A** — Simple directive: "you are a careful reader of computer architecture papers"
- **Study B** — Rich persona: computer architect with deep expertise, explicit skepticism
- **Study C** — 5 specialist personas (Dr Microarch, Prof Workloads, Prof Simtools +
  2 topic-matched experts generated dynamically via Gemini Flash) → individual reviews →
  Claude synthesis into a consolidated output

Study C uses `TOPICS.TXT` + Gemini Flash to identify the 2 closest research topics for the
paper, then generates custom expert personas using `expert_1.md` / `expter_2.md` as
few-shot examples.

Output files written to `<output_dir>/`:
- `study_A.md`, `study_B.md`, `study_C_CONSOLIDATED.md`
- `study_C_personas/` — individual persona responses

```bash
# Run all three studies
python scripts/ablation.py ardubal/pdf_1/3695053.3731036.pdf ardubal/ablation_study_1

# Run a single study
python scripts/ablation.py ardubal/pdf_1/3695053.3731036.pdf ardubal/ablation_study_1 --study B

# Run multiple specific studies
python scripts/ablation.py ardubal/pdf_1/3695053.3731036.pdf ardubal/ablation_study_1 --study A,C
```

---

### 4. `scripts/run_ablations.py`

Orchestrates `ablation.py` (or `evaluate_ablation.py`) across all students and papers
in parallel. Auto-discovers PDFs from `<student>/pdf_1/` and `<student>/pdf_2/`.
**Idempotent** — skips any output files that already exist, so safe to re-run after failures.

**Current students:** amittal26, ardubal, chithra, ian, kannakaranko, naggarwal28, noah,
rnjain, selagamsetty, vramadas, weichu

```bash
# Run all ablations for all students, both papers (3 workers)
python scripts/run_ablations.py

# Re-run failures (safe — skips completed studies)
python scripts/run_ablations.py

# Subset options
python scripts/run_ablations.py --paper 1
python scripts/run_ablations.py --students ardubal,chithra
python scripts/run_ablations.py --study B          # only Study B
python scripts/run_ablations.py --workers 5

# Run pairwise evaluations (A vs B, A vs C, B vs C) for all students
python scripts/run_ablations.py --eval pairwise

# Run vs-gauntlet evaluations (each study vs CONSOLIDATED_REVIEW) for all students
python scripts/run_ablations.py --eval vs-gauntlet

# Combine flags
python scripts/run_ablations.py --eval pairwise --paper 1 --students ardubal
```

---

### 5. `scripts/evaluate_ablation.py`

Blind Gemini evaluation comparing ablation study outputs against each other or against
the Gauntlet CONSOLIDATED_REVIEW. Same 3-run / randomized A/B methodology as `evaluate.py`.
**Idempotent** — skips existing output files.

**vs-gauntlet mode** (default): each Study A/B/C vs `gauntlet_review_N/CONSOLIDATED_REVIEW.md`
- Output: `eval_study_A.md`, `eval_study_B.md`, `eval_study_C.md`

**pairwise mode**: Study A vs B, A vs C, B vs C
- Output: `eval_AvB.md`, `eval_AvC.md`, `eval_BvC.md`

All outputs written into the `--ablation-dir`.

```bash
# vs-gauntlet: all three studies
python scripts/evaluate_ablation.py ardubal --ablation-dir ardubal/ablation_study_1

# vs-gauntlet: specific study
python scripts/evaluate_ablation.py ardubal --ablation-dir ardubal/ablation_study_1 --studies A

# pairwise: all pairs
python scripts/evaluate_ablation.py ardubal --ablation-dir ardubal/ablation_study_1 --mode pairwise

# pairwise: specific pair
python scripts/evaluate_ablation.py ardubal --ablation-dir ardubal/ablation_study_1 --mode pairwise --studies A,B

# Paper 2
python scripts/evaluate_ablation.py ardubal --study-num 2 --ablation-dir ardubal/ablation_study_2 --mode pairwise
```

## Typical Workflow

```bash
# Step 1: After Gauntlet reviews are copied into gauntlet_review_1/ for each student
python scripts/consolidate.py --all --review 1

# Step 2: After students submit their reviews
python scripts/evaluate.py ardubal --review 1
# (or run manually per student)

# Step 3: Run ablation studies across all students (takes ~15-20 min at 3 workers)
python scripts/run_ablations.py

# Step 4: Evaluate — pairwise (studies vs each other)
python scripts/run_ablations.py --eval pairwise

# Step 5: Evaluate — vs Gauntlet
python scripts/run_ablations.py --eval vs-gauntlet
```
